Guía completa para desplegar el OTel Demo en Kubernetes  ·  Documentación oficial

¿Qué es el OTel Demo?

El OpenTelemetry Demo es una aplicación de microservicios de referencia mantenida por la CNCF que demuestra en la práctica el uso de trazas, métricas y logs con OpenTelemetry. Incluye más de 20 servicios escritos en distintos lenguajes, un frontend web, un generador de carga y el stack completo de observabilidad (Collector, Jaeger, Prometheus, Grafana).

Prerequisitos

Antes de comenzar asegúrate de tener instaladas y configuradas las siguientes herramientas:

HerramientaVersión mínimaPropósito
kubectlv1.24+Gestión del clúster Kubernetes
Helmv3.9+Gestor de paquetes para Kubernetes
Clúster Kubernetesv1.24+kind, minikube, EKS, GKE, AKS, etc.
Recursos mínimos recomendados: El demo requiere al menos 6 GB de RAM y 4 vCPUs disponibles en el clúster. Para entornos locales (kind / minikube) configura estos límites antes de continuar.

Verifica que tienes acceso al clúster:

kubectl cluster-info
kubectl get nodes

Verifica la versión de Helm:

helm version
2

Agregar el repositorio Helm de OTel

El chart oficial de OpenTelemetry Demo está publicado en el repositorio Helm de la CNCF OpenTelemetry. Agrégalo y actualiza el índice local: 

helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
helm repo update
¿Qué hace este comando?
helm repo add registra la URL del repositorio bajo el alias open-telemetry. helm repo update descarga el índice actualizado con la lista de todos los charts disponibles y sus versiones.

Puedes confirmar que el chart está disponible:

helm search repo open-telemetry/opentelemetry-demo

La salida muestra la versión del chart y la versión de la aplicación:

NAME                                    CHART VERSION  APP VERSION  DESCRIPTION
open-telemetry/opentelemetry-demo       0.x.x          1.x.x        OpenTelemetry Demo
3

Crear el Namespace

Aislar el demo en su propio namespace facilita la gestión de recursos y su posterior limpieza. 

kubectl create namespace otel-demo
¿Qué es un Namespace?
Un Namespace en Kubernetes es un mecanismo de aislamiento lógico dentro del mismo clúster. Permite organizar recursos (Pods, Services, ConfigMaps…) en grupos independientes, aplicar políticas de acceso separadas y evitar colisiones de nombres.

Verifica que fue creado correctamente:

kubectl get namespace otel-demo
4

Personalizar valores (opcional)

El chart de Helm acepta un archivo values.yaml para sobrescribir la configuración por defecto. Este paso es Opcional para un despliegue estándar, pero Requerido para entornos de producción o cuando deseas ajustar recursos.

Descarga los valores por defecto para inspeccionarlos:

helm show values open-telemetry/opentelemetry-demo > my-values.yaml

Las secciones más relevantes para ajustar:

Sección en values.yamlDescripción
components.<service>.resourcesCPU / Memory requests y limits por servicio
components.<service>.enabledHabilitar o deshabilitar servicios individuales
opentelemetry-collector.configPipelines del OTel Collector (receivers, processors, exporters)
jaeger.enabledDesplegar Jaeger como backend de trazas (default: true)
prometheus.enabledDesplegar Prometheus (default: true)
grafana.enabledDesplegar Grafana (default: true)
loadgenerator.enabledGenerador de carga sintética Locust (default: true)
Ejemplo mínimo de my-values.yaml para reducir recursos en local: 
# my-values.yaml — ajuste de recursos para entorno local
components:
  cartservice:
    resources:
      requests:
        memory: "128Mi"
        cpu: "100m"
  frontend:
    resources:
      requests:
        memory: "256Mi"
        cpu: "200m"

Instalar el chart con Helm

Instalación estándar (sin archivo de valores personalizados):

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --wait

Instalación con valores personalizados:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --values my-values.yaml \
  --wait
Desglose del comando:
  • helm install — instala el chart en el clúster.
  • my-otel-demo — nombre del release (puede ser cualquier nombre).
  • open-telemetry/opentelemetry-demo — chart a instalar (repo/chart).
  • --namespace otel-demo — despliega todos los recursos en este namespace.
  • --values my-values.yaml — sobrescribe los valores por defecto.
  • --wait — bloquea el terminal hasta que todos los Pods estén Ready.
Tiempo de instalación: La primera vez puede tardar entre 5 y 10 minutos dependiendo de la velocidad de descarga de las imágenes de contenedor. El flag --wait mantiene el proceso activo hasta que el despliegue esté completo.

Si deseas especificar una versión concreta del chart:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --version 0.33.0 \
  --wait

Verificar el despliegue

Una vez instalado, comprueba que todos los recursos están corriendo correctamente.

Ver todos los Pods del namespace:

kubectl get pods -n otel-demo

Todos los pods deben tener estado Running y sus contenedores READY.

Ver todos los Services:

kubectl get services -n otel-demo

Ver el release de Helm:

helm list -n otel-demo

Ver eventos en caso de problemas:

kubectl get events -n otel-demo --sort-by=.lastTimestamp

Ver logs de un Pod específico:

kubectl logs -n otel-demo \
  deployment/my-otel-demo-frontend \
  --follow
Estado saludable esperado: Deberías ver alrededor de 20–25 Pods en estado Running. Si alguno está en CrashLoopBackOff o Pending, revisa los logs y los eventos del Pod con kubectl describe pod <pod-name> -n otel-demo.

Acceder a los servicios con Port-Forward

Por defecto los services son de tipo ClusterIP (solo accesibles dentro del clúster). Usa kubectl port-forward para exponer cada servicio en tu máquina local sin necesidad de un Ingress o LoadBalancer.

¿Qué es port-forward?
kubectl port-forward crea un túnel TCP entre tu máquina local y un Pod o Service dentro del clúster. El tráfico que llega al puerto local se redirige al puerto del Pod/Service. Es ideal para desarrollo y debugging; no es para producción.

Frontend (Tienda web):

kubectl port-forward -n otel-demo \
  svc/my-otel-demo-frontend 8080:8080

Abre en el navegador: http://localhost:8080

Jaeger (Trazas distribuidas):

kubectl port-forward -n otel-demo \
  svc/my-otel-demo-jaeger-query 16686:16686

Abre en el navegador: http://localhost:16686

Grafana (Dashboards de métricas):

kubectl port-forward -n otel-demo \
  svc/my-otel-demo-grafana 3000:80

Abre en el navegador: http://localhost:3000 (usuario: admin / contraseña: admin)

Prometheus (Explorador de métricas):

kubectl port-forward -n otel-demo \
  svc/my-otel-demo-prometheus 9090:9090

Abre en el navegador: http://localhost:9090

Generador de carga — Locust UI:

kubectl port-forward -n otel-demo \
  svc/my-otel-demo-loadgenerator 8089:8089

Abre en el navegador: http://localhost:8089

Tip: Para ejecutar múltiples port-forwards a la vez, abre una terminal separada por cada comando o usa el flag & al final del comando para ejecutarlos en background.

Explorar la observabilidad

Con el demo en funcionamiento y el generador de carga activo, puedes observar telemetría en tiempo real en las tres herramientas incluidas.

🔍 Trazas en Jaeger

  1. Abre http://localhost:16686.
  2. En el menú Service, selecciona cualquier servicio (ej. frontend).
  3. Haz clic en Find Traces.
  4. Selecciona una traza para ver el recorrido completo de una petición a través de todos los microservicios, latencias y atributos OTel.

📊 Métricas en Grafana

  1. Abre http://localhost:3000.
  2. Ve a Dashboards → OpenTelemetry Demo.
  3. Explora los dashboards precargados: latencias, tasas de error, throughput, recursos de red.

📈 Queries en Prometheus

  1. Abre http://localhost:9090.
  2. Ejecuta una query PromQL, por ejemplo:
# Tasa de peticiones HTTP en los últimos 5 minutos
rate(http_server_duration_milliseconds_count[5m])
¡Listo! Tienes el OTel Demo completamente funcional en Kubernetes con trazas, métricas y logs fluyendo a través del OpenTelemetry Collector hacia Jaeger, Prometheus y Grafana.

Comandos de limpieza (cuando ya no necesites el demo):

# Desinstalar el release de Helm
helm uninstall my-otel-demo -n otel-demo

# Eliminar el namespace (borra todos los recursos)
kubectl delete namespace otel-demo
