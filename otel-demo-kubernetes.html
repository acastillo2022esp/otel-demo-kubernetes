¿Qué es un Namespace? Un Namespace en Kubernetes es un mecanismo de aislamiento lógico. Permite organizar recursos (Pods, Services, ConfigMaps) en grupos independientes, aplicar políticas de acceso separadas y facilitar la limpieza posterior.

Instalar el chart con Helm

Desplegar todos los microservicios en el clúster

Instalación estándar:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --wait

Con valores personalizados:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --values my-values.yaml \
  --wait
ℹ
Desglose del comando:
  • my-otel-demo — nombre del release (puede ser cualquier nombre)
  • open-telemetry/opentelemetry-demo — chart a instalar
  • --namespace otel-demo — despliega en el namespace creado
  • --wait — bloquea hasta que todos los Pods estén Ready
⚠
Tiempo de instalación: La primera vez puede tardar 5–10 minutos por descarga de imágenes de contenedor.

Acceder a los servicios

Port-forward para acceder desde tu máquina local
ℹ
¿Qué es port-forward? kubectl port-forward crea un túnel TCP entre tu máquina local y un Service del clúster. El tráfico al puerto local se redirige al Pod. Ideal para desarrollo y debugging, no para producción.
# Frontend — http://localhost:8080
kubectl port-forward -n otel-demo svc/my-otel-demo-frontend 8080:8080

# Jaeger (Trazas) — http://localhost:16686
kubectl port-forward -n otel-demo svc/my-otel-demo-jaeger-query 16686:16686

# Grafana (Dashboards) — http://localhost:3000  (admin/admin)
kubectl port-forward -n otel-demo svc/my-otel-demo-grafana 3000:80

# Prometheus — http://localhost:9090
kubectl port-forward -n otel-demo svc/my-otel-demo-prometheus 9090:9090

# Locust (Carga) — http://localhost:8089
kubectl port-forward -n otel-demo svc/my-otel-demo-loadgenerator 8089:8089
⚠
Abre una terminal separada por cada port-forward, o añade & al final para ejecutar en background.

Red virtual (VCN)

OKE necesita una Virtual Cloud Network con subnets
✅
Recomendado — Quick Create: Al crear el clúster en el Paso 4, selecciona "Quick Create". OCI genera automáticamente la VCN con todas las subnets y security lists. No necesitas hacer este paso manualmente.

Si prefieres crear la VCN manualmente:

# Obtener OCID del compartment raíz
oci iam compartment list --all \
  --query "data[?\"lifecycle-state\"=='ACTIVE'].id | [0]"

# Crear VCN
oci network vcn create \
  --compartment-id <COMPARTMENT_OCID> \
  --display-name otel-demo-vcn \
  --cidr-block 10.0.0.0/16 \
  --dns-label oteldemo

Crear el clúster OKE

Oracle Kubernetes Engine — control plane gratuito, nodos ARM Always Free

Opción A — Desde la OCI Console (recomendado):

  1. Menú hamburguesa → Developer Services → Kubernetes Clusters (OKE).
  2. Clic en "Create cluster" → selecciona "Quick create" → Launch workflow.
  3. Configura los siguientes valores:
    CampoValor recomendado
    Nameotel-demo-cluster
    Kubernetes versionLa más reciente disponible
    VisibilityPublic endpoint (para acceder con kubectl)
    ShapeVM.Standard.A1.Flex (ARM — Always Free)
    OCPUs por nodo2
    Memory por nodo12 GB
    Number of nodes2 (total: 4 OCPUs / 24 GB = límite Always Free)
  4. Clic en "Next" → "Create cluster".
  5. Espera ~5–10 minutos hasta que el estado sea Active.
⚠
Límite Always Free ARM: Son exactamente 4 OCPUs + 24 GB RAM en total. Usa 2 nodos × 2 OCPUs / 12 GB para no salir del tier gratuito.

Opción B — Desde la CLI:

# Crear clúster OKE
oci ce cluster create \
  --compartment-id <COMPARTMENT_OCID> \
  --name otel-demo-cluster \
  --vcn-id <VCN_OCID> \
  --kubernetes-version v1.30.1 \
  --service-lb-subnet-ids '["<SUBNET_OCID>"]' \
  --endpoint-subnet-id <SUBNET_OCID> \
  --endpoint-public-ip-enabled true

# Crear node pool ARM Always Free
oci ce node-pool create \
  --cluster-id <CLUSTER_OCID> \
  --compartment-id <COMPARTMENT_OCID> \
  --name otel-demo-pool \
  --node-shape VM.Standard.A1.Flex \
  --node-shape-config '{"ocpus": 2, "memoryInGBs": 12}' \
  --size 2 \
  --node-image-name "Oracle-Linux-8.x-aarch64-2024" \
  --placement-configs '[{"availabilityDomain":"<AD>","subnetId":"<SUBNET_OCID>"}]'

Obtener kubeconfig del clúster OKE

Conectar kubectl al clúster de Oracle Cloud
# Obtener OCID del clúster
oci ce cluster list \
  --compartment-id <COMPARTMENT_OCID> \
  --query "data[?name=='otel-demo-cluster'].id | [0]" \
  --raw-output

# Generar y fusionar kubeconfig
oci ce cluster create-kubeconfig \
  --cluster-id <CLUSTER_OCID> \
  --file $HOME/.kube/config \
  --region us-ashburn-1 \
  --token-version 2.0.0 \
  --kube-endpoint PUBLIC_ENDPOINT
ℹ
  • --file $HOME/.kube/config — fusiona el contexto OKE con el kubeconfig existente
  • --token-version 2.0.0 — tokens de corta duración, más seguro
  • --kube-endpoint PUBLIC_ENDPOINT — conecta al endpoint público

Verifica la conexión — deberías ver los 2 nodos ARM en estado Ready:

Instalar OTel Demo con ajuste para ARM

El chart soporta aarch64 nativamente desde v0.28+

Crea un archivo oci-values.yaml optimizado para los nodos ARM Always Free:

# oci-values.yaml — ajustado para 4 OCPUs / 24 GB ARM Always Free
default:
  resources:
    requests: { cpu: "50m", memory: "64Mi" }
    limits:   { cpu: "200m", memory: "256Mi" }

components:
  frontend:
    resources:
      requests: { cpu: "200m", memory: "256Mi" }
      limits:   { cpu: "500m", memory: "512Mi" }
  checkoutservice:
    resources:
      requests: { cpu: "100m", memory: "128Mi" }
  cartservice:
    resources:
      requests: { cpu: "100m", memory: "128Mi" }

opentelemetry-collector:
  resources:
    requests: { cpu: "200m", memory: "256Mi" }
    limits:   { cpu: "500m", memory: "512Mi" }

prometheus:
  server:
    resources:
      requests: { cpu: "200m", memory: "512Mi" }

grafana:
  resources:
    requests: { cpu: "100m", memory: "256Mi" }

Instalar el chart:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --values oci-values.yaml \
  --wait \
  --timeout 15m
⚠
¿Por qué --timeout 15m? En nodos ARM Always Free la descarga de imágenes puede tardar más. El timeout extendido evita que Helm cancele el despliegue antes de que termine.

Crear el clúster kind

Clúster Kubernetes local listo en ~60 segundos

Crea un archivo de configuración kind-config.yaml para ajustar los recursos:

# kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    kubeadmConfigPatches:
      - |
        kind: InitConfiguration
        nodeRegistration:
          kubeletExtraArgs:
            node-labels: "ingress-ready=true"
    extraPortMappings:
      - containerPort: 80
        hostPort: 80
        protocol: TCP
      - containerPort: 443
        hostPort: 443
        protocol: TCP
  - role: worker
  - role: worker

Crear el clúster con esa configuración:

# Crear clúster (tarda ~60 segundos)
kind create cluster \
  --name otel-demo \
  --config kind-config.yaml

# Verificar que el clúster está corriendo
kubectl cluster-info --context kind-otel-demo
kubectl get nodes
✅
Deberías ver 3 nodos (control-plane + 2 worker) en estado Ready.
ℹ
Tip — múltiples contextos: Si tienes otros clústeres configurados, asegúrate de usar el contexto correcto: kubectl config use-context kind-otel-demo

Parsear información útil de los Logs

Extraer campos estructurados con Parsing Rules en Coralogix

Los logs del OTel Demo llegan en formato JSON. Coralogix permite extraer campos específicos mediante Parsing Rules para convertir texto en campos consultables y filtrables.

Configurar una Parsing Rule en Coralogix:

  1. En la consola, ve a Data Flow → Parsing Rules.
  2. Haz clic en "New Rule Group".
  3. Configura el scope: Application = otel-demo, Subsystem = *.
  4. Agrega una regla de tipo JSON Extract para el campo text y mapea los campos extraídos.
  5. Guarda y verifica en Explore → Logs que los campos aparecen como columnas.
ℹ
Ejemplo — Regex Parsing Rule para extraer el http.method, http.status_code y service.name del body del log:
# Expresión regular de ejemplo para logs de frontend
(?P<http_method>GET|POST|PUT|DELETE|PATCH)\s(?P<http_path>\/[^\s]*)\s.*?status=(?P<http_status>\d{3})
💡
Campos recomendados a parsear del OTel Demo:
  • service.name — nombre del microservicio origen
  • http.method + http.route + http.status_code — peticiones HTTP
  • span_id + trace_id — correlación entre logs y trazas
  • exception.type + exception.message — errores de aplicación
  • k8s.pod.name + k8s.namespace.name — contexto de infraestructura

Verifica el resultado en Explore → Logs usando el campo extraído:

# Query de ejemplo en Lucene (DataPrime también disponible)
http_status:5* AND service_name:checkoutservice

Crear una métrica con Events2Metrics

Convertir logs y trazas en métricas de largo plazo para retención y alertas
ℹ
¿Qué es Events2Metrics? Events2Metrics convierte logs o spans individuales en métricas agregadas (counter, gauge, histogram) que se almacenan de forma permanente con bajo costo. Ideal para retención de KPIs más allá de la ventana de logs.

Ejemplo: Métrica de tasa de errores HTTP por servicio

  1. Ve a Data Flow → Events2Metrics y haz clic en "Add Metric".
  2. Selecciona fuente Spans (trazas).
  3. Configura los campos:
CampoValor
Metric nameotel_demo_http_errors_total
Metric typeCounter
Filterhttp.status_code >= 400
Dimensions (labels)service.name, http.route, http.status_code
Applicationotel-demo

Segundo ejemplo: Latencia P95 del checkout

CampoValor
Metric nameotel_demo_checkout_duration_ms
Metric typeHistogram
Value fieldduration_ms
Filterservice.name:checkoutservice
Dimensionsservice.name, span.name
✅
Tras 2–5 minutos, las métricas aparecerán en Explore → Metrics y podrás consultarlas con PromQL: rate(otel_demo_http_errors_total[5m])

Configurar Alertas proactivas

Detección temprana de problemas antes de que impacten a los usuarios

Ve a Alerts → New Alert y crea las siguientes alertas para monitorear el OTel Demo:

AlertaTipoCondiciónSeveridadPropósito
Alta tasa de errores 5xxMetric Alertrate(otel_demo_http_errors_total{status_code=~"5.."}[5m]) > 0.1CriticalDetectar fallos del servidor
Latencia P95 elevadaMetric Alerthistogram_quantile(0.95, rate(http_server_duration_milliseconds_bucket[5m])) > 2000HighDegradación de rendimiento
Pod en CrashLoopBackOffLog AlertLog text contains CrashLoopBackOffCriticalFallo de aplicación
Excepción no controladaLog AlertSeverity = ERROR AND exception.type exists — más de 10 en 5 minHighErrores de aplicación frecuentes
Checkoutservice sin tráficoMetric Alert (absence)rate(http_server_duration_milliseconds_count{service="checkoutservice"}[10m]) == 0HighServicio crítico caído
Uso de memoria > 85%Metric Alert(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) > 0.85MediumRiesgo de OOM en nodos
OTel Collector sin datosMetric Alert (absence)No hay datos en el exporter en 10 minCriticalPipeline de telemetría roto

Configurar notificaciones para las alertas:

  1. En cada alerta, ve a la sección Notify.
  2. Elige el canal: Email, Slack, PagerDuty, Webhook, etc.
  3. Configura el Notification Group (quién recibe qué severidad).
  4. Activa el Alert Suppression para evitar flapping en alertas ruidosas.

    Diferenciador clave frente a competidores: métricas a largo plazo sin código.

    • Ve a Data Flow → Events2Metrics.
    • Muestra la métrica otel_demo_http_errors_total (counter desde spans).
    • Abre Explore → Metrics y ejecuta: rate(otel_demo_http_errors_total[5m])
    • Mensaje clave: "Sin un solo cambio en el código de la aplicación, están midiendo la tasa de errores HTTP por servicio con retención de meses, no de horas."
    • Si el cliente usa Prometheus: "Es compatible con PromQL. Sus dashboards de Grafana existentes funcionarían sin tocarlos."

    Min 18–20 · Cierre y preguntas

    Cierre — Resumen de valor y próximos pasos

    Termina con claridad sobre lo que vio y cuál es el siguiente paso.

    • Resume en 3 frases: "Vieron datos fluyendo en tiempo real, trazas distribuidas correlacionadas con logs, y alertas proactivas. Todo sin modificar el código de la aplicación, solo configurando el OTel Collector."
    • Pregunta abierta: "¿Qué parte les pareció más relevante para su entorno actual?"
    • Próximo paso concreto: propón un PoC de 2 semanas con su propia aplicación conectada a una cuenta trial de Coralogix.
    • Deja abierta la página con el dashboard visible — impacto visual mientras hablan.
