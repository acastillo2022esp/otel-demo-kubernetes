¿Qué es el OTel Demo?

El OpenTelemetry Demo es una aplicación de microservicios de referencia mantenida por la CNCF que demuestra en la práctica el uso de trazas, métricas y logs con OpenTelemetry. Incluye más de 20 servicios escritos en distintos lenguajes, un frontend web, un generador de carga y el stack completo de observabilidad (Collector, Jaeger, Prometheus, Grafana).

Prerequisitos

Antes de comenzar asegúrate de tener instaladas y configuradas las siguientes herramientas:

2

Agregar el repositorio Helm de OTel

El chart oficial está publicado en el repositorio Helm de la CNCF OpenTelemetry:

helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
helm repo update
¿Qué hace este comando?
helm repo add registra la URL bajo el alias open-telemetry. helm repo update descarga el índice actualizado con todos los charts disponibles.

Confirma que el chart está disponible:

helm search repo open-telemetry/opentelemetry-demo
3

Crear el Namespace

Aislar el demo en su propio namespace facilita la gestión de recursos y su posterior limpieza.

kubectl create namespace otel-demo
¿Qué es un Namespace?
Un Namespace en Kubernetes es un mecanismo de aislamiento lógico dentro del mismo clúster. Permite organizar recursos (Pods, Services, ConfigMaps…) en grupos independientes y evitar colisiones de nombres. 
kubectl get namespace otel-demo
4

Personalizar valores Opcional

El chart acepta un archivo values.yaml para sobrescribir la configuración por defecto:

helm show values open-telemetry/opentelemetry-demo > my-values.yaml
Sección en values.yamlDescripción
components.<service>.resourcesCPU / Memory requests y limits por servicio
components.<service>.enabledHabilitar o deshabilitar servicios individuales
opentelemetry-collector.configPipelines del OTel Collector
jaeger.enabledDesplegar Jaeger como backend de trazas (default: true)
prometheus.enabledDesplegar Prometheus (default: true)
grafana.enabledDesplegar Grafana (default: true)
loadgenerator.enabledGenerador de carga sintética Locust (default: true)
5

Instalar el chart con Helm

Instalación estándar:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --wait

Con valores personalizados:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --values my-values.yaml \
  --wait
Desglose:
  • my-otel-demo — nombre del release.
  • --namespace otel-demo — despliega en el namespace creado.
  • --wait — bloquea hasta que todos los Pods estén Ready.
Tiempo de instalación: Entre 5 y 10 minutos la primera vez por descarga de imágenes.

Acceder a los servicios con Port-Forward

¿Qué es port-forward?
kubectl port-forward crea un túnel TCP entre tu máquina local y un Pod/Service del clúster. Es ideal para desarrollo y debugging, no para producción.

Frontend:

kubectl port-forward -n otel-demo svc/my-otel-demo-frontend 8080:8080

→ http://localhost:8080

Jaeger (Trazas):

kubectl port-forward -n otel-demo svc/my-otel-demo-jaeger-query 16686:16686

→ http://localhost:16686

Grafana (Dashboards):

kubectl port-forward -n otel-demo svc/my-otel-demo-grafana 3000:80

→ http://localhost:3000 (admin / admin)

Prometheus:

kubectl port-forward -n otel-demo svc/my-otel-demo-prometheus 9090:9090

→ http://localhost:9090

Locust (Generador de carga):

kubectl port-forward -n otel-demo svc/my-otel-demo-loadgenerator 8089:8089

→ http://localhost:8089

Crear cuenta en Oracle Cloud (Always Free)

Si no tienes cuenta en OCI, regístrate en el tier gratuito. No requiere tarjeta de crédito para los recursos Always Free, aunque el proceso de registro la solicita como verificación.

  1. Ve a signup.cloud.oracle.com.
  2. Selecciona "Start for free" y completa el formulario.
  3. Elige una región Home (recomendado: us-ashburn-1 o us-phoenix-1 por mayor disponibilidad de recursos ARM).
  4. Verifica tu email y completa la verificación de identidad.
  5. Una vez activada la cuenta, accede a la OCI Console.
Recursos Always Free disponibles:
  • 4 OCPUs ARM Ampere A1 + 24 GB RAM (compartibles entre VMs)
  • 2 VMs AMD (1 OCPU / 1 GB RAM cada una)
  • 200 GB almacenamiento en bloque
  • OKE Control Plane — gratis
  • 10 TB de egress de red al mes

Instalar y configurar la OCI CLI

La OCI CLI permite gestionar todos los recursos de Oracle Cloud desde la terminal. Es la herramienta principal para crear el clúster y obtener el kubeconfig.

Instalar en macOS:

brew install oci-cli

Instalar en Linux:

bash -c "$(curl -fsSL https://raw.githubusercontent.com/oracle/oci-cli/master/scripts/install/install.sh)"

Verificar instalación:

oci --version

Configurar la CLI (setup inicial):

oci setup config
Este comando interactivo te pedirá:
  1. User OCID: lo encuentras en OCI Console → Profile → tu usuario → OCID.
  2. Tenancy OCID: OCI Console → Administration → Tenancy Details → OCID.
  3. Region: la región Home de tu cuenta (ej. us-ashburn-1).
  4. Generate new API key pair: selecciona Y.
Guarda la clave pública generada en ~/.oci/oci_api_key_public.pem y súbela en OCI Console → Profile → API Keys → Add API Key.

Verificar que la CLI tiene acceso:

oci iam region list --output table
3

Crear la red virtual (VCN) para el clúster

OKE necesita una Virtual Cloud Network (VCN) con subnets para los nodos del clúster y el load balancer. La forma más rápida es usar el Quick Create de OKE que genera la VCN automáticamente.

Opción recomendada — Quick Create: Cuando crees el clúster OKE en el siguiente paso, selecciona "Quick Create". OCI creará automáticamente la VCN con todas las subnets y security lists necesarias. No necesitas crear la VCN manualmente.

Si prefieres crear la VCN manualmente por la CLI, obtén primero el OCID de tu compartment: 

# Obtener el OCID del compartment raíz (tenancy)
oci iam compartment list --all --query "data[?\"lifecycle-state\"=='ACTIVE'].id | [0]"
# Crear VCN
oci network vcn create \
  --compartment-id <COMPARTMENT_OCID> \
  --display-name otel-demo-vcn \
  --cidr-block 10.0.0.0/16 \
  --dns-label oteldemo
4

Crear el clúster OKE (Oracle Kubernetes Engine)

OKE es el servicio Kubernetes gestionado de OCI. El control plane es gratuito; solo pagas por los nodos worker. Con los recursos ARM Always Free puedes tener un clúster completamente funcional sin costo.

Opción A — Desde la OCI Console (recomendado para empezar):

  1. En la OCI Console, ve al menú hamburguesa → Developer Services → Kubernetes Clusters (OKE).
  2. Haz clic en "Create cluster".
  3. Selecciona "Quick create" y haz clic en Launch workflow.
  4. Configura:
    • Name: otel-demo-cluster
    • Kubernetes version: selecciona la más reciente disponible.
    • Visibility: Public endpoint (para acceder con kubectl desde tu máquina).
    • Shape: VM.Standard.A1.Flex (ARM — Always Free).
    • OCPUs por nodo: 2 | Memory: 12 GB.
    • Number of nodes: 2 (total 4 OCPUs / 24 GB — dentro del Always Free).
  5. Haz clic en "Next" y luego en "Create cluster".
  6. Espera ~5–10 minutos hasta que el estado sea Active.
Configuración Always Free exacta: Los recursos ARM Always Free son 4 OCPUs + 24 GB RAM en total. Distribuye en máximo 2 nodos con 2 OCPUs / 12 GB cada uno para no salir del tier gratuito.

Opción B — Desde la CLI:

# Crear clúster OKE (reemplaza los OCIDs con los tuyos)
oci ce cluster create \
  --compartment-id <COMPARTMENT_OCID> \
  --name otel-demo-cluster \
  --vcn-id <VCN_OCID> \
  --kubernetes-version v1.30.1 \
  --service-lb-subnet-ids '["<SUBNET_OCID>"]' \
  --endpoint-subnet-id <SUBNET_OCID> \
  --endpoint-public-ip-enabled true

# Crear node pool con instancias ARM Always Free
oci ce node-pool create \
  --cluster-id <CLUSTER_OCID> \
  --compartment-id <COMPARTMENT_OCID> \
  --name otel-demo-pool \
  --node-shape VM.Standard.A1.Flex \
  --node-shape-config '{"ocpus": 2, "memoryInGBs": 12}' \
  --size 2 \
  --node-image-name "Oracle-Linux-8.x-aarch64-2024" \
  --placement-configs '[{"availabilityDomain":"<AD>","subnetId":"<SUBNET_OCID>"}]'

Obtener el kubeconfig del clúster OKE

El kubeconfig es el archivo de configuración que permite a kubectl conectarse al clúster OKE. La CLI de OCI lo genera y fusiona automáticamente con tu configuración local.

Obtén el OCID del clúster creado:

oci ce cluster list \
  --compartment-id <COMPARTMENT_OCID> \
  --query "data[?name=='otel-demo-cluster'].id | [0]" \
  --raw-output

Genera y guarda el kubeconfig:

oci ce cluster create-kubeconfig \
  --cluster-id <CLUSTER_OCID> \
  --file $HOME/.kube/config \
  --region us-ashburn-1 \
  --token-version 2.0.0 \
  --kube-endpoint PUBLIC_ENDPOINT
Parámetros clave:
  • --file $HOME/.kube/config — fusiona el contexto OKE con el kubeconfig existente.
  • --token-version 2.0.0 — usa tokens de corta duración (más seguro).
  • --kube-endpoint PUBLIC_ENDPOINT — conecta por el endpoint público del cluster.

Verifica que kubectl puede conectarse al clúster OKE:

kubectl get nodes
kubectl cluster-info

Deberías ver los 2 nodos ARM en estado Ready:

10.0.xx.yyy   Ready    <none>   5m    v1.30.1

Instalar el OTel Demo con ajuste para ARM

Los nodos ARM A1 de OCI son arquitectura aarch64. El chart de OTel Demo soporta ARM de forma nativa desde la versión 0.28+. Sin embargo, se recomienda ajustar los recursos al tier gratuito disponible.

Crea un archivo oci-values.yaml optimizado para los nodos ARM Always Free:

# oci-values.yaml — ajuste para OCI ARM Always Free (4 OCPUs / 24 GB total)
default:
  resources:
    requests:
      cpu: "50m"
      memory: "64Mi"
    limits:
      cpu: "200m"
      memory: "256Mi"

components:
  frontend:
    resources:
      requests: { cpu: "200m", memory: "256Mi" }
      limits:   { cpu: "500m", memory: "512Mi" }
  checkoutservice:
    resources:
      requests: { cpu: "100m", memory: "128Mi" }
  cartservice:
    resources:
      requests: { cpu: "100m", memory: "128Mi" }
  productcatalogservice:
    resources:
      requests: { cpu: "100m", memory: "128Mi" }

opentelemetry-collector:
  resources:
    requests: { cpu: "200m", memory: "256Mi" }
    limits:   { cpu: "500m", memory: "512Mi" }

prometheus:
  server:
    resources:
      requests: { cpu: "200m", memory: "512Mi" }

grafana:
  resources:
    requests: { cpu: "100m", memory: "256Mi" }

Instalar el chart:

helm install my-otel-demo open-telemetry/opentelemetry-demo \
  --namespace otel-demo \
  --values oci-values.yaml \
  --wait \
  --timeout 15m
¿Por qué --timeout 15m?
En los nodos ARM Always Free la descarga de las imágenes de contenedor puede tardar más que en nodos de mayor capacidad. El timeout extendido evita que Helm cancele el despliegue prematuramente.

Explorar la observabilidad en OCI

Además de Jaeger, Prometheus y Grafana incluidos en el demo, OCI ofrece servicios nativos de observabilidad que puedes integrar con el OTel Collector.

Servicio OCIEquivalente OTelIntegración
OCI Application Performance Monitoring (APM)Trazas (Jaeger)Exportar trazas via OTLP al APM de OCI
OCI LoggingLogsExportar logs via OCI Logging exporter
OCI MonitoringMétricas (Prometheus)Exportar métricas via remote_write
Integrar OTel Collector con OCI APM:
El OTel Collector incluye un exporter nativo para OCI APM. Añade en el values.yaml dentro de opentelemetry-collector.config.exporters: 
exporters:
  otlp/oci-apm:
    endpoint: "https://<APM_DOMAIN>.apm-agt.<region>.oci.oraclecloud.com/20200101/opentelemetry"
    headers:
      Authorization: "dataKey <OCI_APM_PRIVATE_DATA_KEY>"
¡Despliegue completo en OCI Always Free! Tienes el OTel Demo corriendo en Kubernetes gestionado (OKE) con nodos ARM sin costo, con observabilidad completa en Jaeger, Prometheus y Grafana, y la opción de integrar los servicios nativos de OCI.
